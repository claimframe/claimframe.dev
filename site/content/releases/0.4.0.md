Claimframe 0.4.0 adds a way to share your vault with another person, edit its contents outside the app, and bring them into a fresh vault. It also simplifies entity naming and replaces the Linux AppImage with standard packages.

## Share a vault

Export your vault as one `.cftext` file and send it through your chosen channel. The recipient imports it into a fresh vault and gets an independent copy of the current claims, relationships, and source and evidence references. No Claimframe account or cloud service is required.

This is the recommended way to hand off vault content. Later edits on either side do not update the other. Follow [Share a vault](/guide/how-to/share-vault/) for the sender and recipient steps.

## Edit your vault as text

The new CFText format also lets you open an export in your preferred text editor, make changes, and import the result into a fresh vault. Your original vault stays intact.

CFText carries current content, not the full transaction and review history, saved queries, or settings. Keep your normal vault backups for recovery. The [CFText reference](/guide/reference/cftext/) explains what carries over and how to edit the file.

## Simpler names and renames

In 0.3.2, renaming an entity kept its previous name as an alias, so queries could still find it by the old name. Claimframe also treated `billing-service`, `billing_service`, and `billing service` as the same name.

In 0.4.0, renaming replaces the name you use to find the entity. Its claims and connections stay intact, but the old name stops resolving and becomes available for another entity. Capitalization is still ignored; punctuation and spaces within a name now matter. You can keep those differently spelled names distinct instead of having them silently refer to the same entity.

For example, rename `billing` to `payments` and use `payments` from then on. A saved query containing `billing ? ?` stays as written, so edit it to `payments ? ?` if you want the same results. If another entity later takes the name `billing`, the old query may find that entity instead.

Original evidence keeps its wording. See [naming rules](/guide/reference/capture-syntax/#current-entity-names) and [saved queries after a rename](/guide/how-to/query-and-save/#after-an-entity-rename) for details.

## Standard Linux installation

Linux downloads now come as DEB and RPM packages, replacing AppImage. Install the package for your distribution with its package manager; it installs the launcher and icon so you can open Claimframe from your application menu. To update, download and install the newer package the same way.

See [Install on Linux](/guide/how-to/install-linux/) for package choices and commands.

## More improvements

- **Extract claims from ordinary documents.** Document Intake previously required assertion lines you had prepared yourself. Now paste ordinary text or open a local text file and review AI-proposed claims alongside their source passages before accepting them. Transcript extraction and review were already available in 0.3.2.
- **Work in several views.** Open another view with `Ctrl/Cmd` + `N` and close a window with `Ctrl/Cmd` + `W`.
- **Reach your content faster.** Browse entities and saved queries in the sidebar, with improvements to query suggestions, review layouts, and loading feedback.
- **Choose your domain vocabulary.** New vaults start with the basic claim relationships. [Adopt a vocabulary](/guide/how-to/manage-vocabulary/) or define your own predicates as needed. Existing vault schemas are retained.

## Before you upgrade

Close other Claimframe windows and MCP sessions using the vault. When you open it in 0.4.0, Claimframe asks before upgrading and automatically creates a backup.

**Older versions cannot open an upgraded vault.** Keep the backup and your previous installer. Read the [upgrade and recovery instructions](/guide/how-to/manage-vault/#upgrade-an-older-vault-to-current-name-naming) before proceeding, especially if you share a vault with an MCP client.
