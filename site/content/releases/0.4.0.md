Version 0.4.0 changes entity-name lookup and Linux desktop packaging. Existing vault users should review the naming and recovery steps before upgrading.

## One current name per entity

Each entity has one stable ID and one current name, unique within a vault under case-insensitive comparison. Capturing another capitalization reuses the entity without changing its displayed name. Explicit rename, including a case-only rename, preserves the ID and stored relationships. Rename cannot take another entity's current name.

Surrounding whitespace is trimmed; interior spaces, punctuation, and Unicode composition are preserved. `billing-service`, `billing_service`, and `"billing service"` are distinct names. Unicode simple case folding does not expand characters: `ß` and `ss` remain distinct. See the [full name comparison rules](/guide/reference/capture-syntax/#current-entity-names).

**Old names stop resolving after rename and become available for reuse.** There are no retained lookup aliases. Domain naming or `aka` claims remain sourced facts, and historical evidence keeps its original wording. Stable vocabulary identifiers are unchanged.

Autocomplete inserts syntax-safe current names as text, without an ID binding. Graph nodes use stored entity IDs, so a changed label preserves the entity's identity and connections.

## Saved queries need review after rename

Saved queries remain exactly as written through rename and migration. After `billing` is renamed to `billing-service`, `billing ? ?` no longer selects the original entity. If another entity later takes `billing`, that query may select the new owner. Edit or recreate saved queries when you need them to follow the renamed entity. See [query guidance](/guide/how-to/query-and-save/#after-an-entity-rename).

## Vault upgrade and recovery

Schema 17 requires explicit confirmation in the desktop picker before upgrading an older supported vault. Close other desktop and MCP sessions using it. The app creates a SQLite backup beside the vault before migration, preserving committed data including the write-ahead log. It preserves entity IDs, relationships, evidence, history, and saved query text.

Empty names or case-insensitive current-name collisions stop migration and roll back changes. **Older apps cannot open schema 17 vaults.** For recovery, close all sessions, keep the original vault and sidecars, and open a copy of the reported backup at a fresh path with the previous app. Resolve reported collisions there before retrying. Follow the [complete upgrade and recovery steps](/guide/how-to/manage-vault/#upgrade-an-older-vault-to-current-name-naming).

## New: export, edit, and import CFText

CFText is new in 0.4.0. Export the current vault as an editable `.cftext` file, change it in your preferred text editor, then import it into a fresh vault. Review the imported content before using the new vault. This workflow lets you move or deliberately revise current logical content while keeping the original vault separate.

CFText is also the recommended way to share vault content with another person instead of passing SQLite database files around. The sender exports one snapshot and shares it through their chosen channel; the recipient imports it into a fresh vault. The result is an independent copy, not synchronization or a shared live vault. Follow [Share a vault](/guide/how-to/share-vault/) for the complete sender and recipient steps.

Import creates new IDs and transactions. It carries current claims and their supported source/evidence metadata, but not complete transaction/review history, saved queries, or settings. CFText is not a replacement for a SQLite backup. See [CFText snapshots](/guide/reference/cftext/) for what carries over, editing rules, and validation.

## Native Linux packages replace AppImage

Linux x86-64 desktop downloads change to a DEB package for Debian/Ubuntu-family package managers and an RPM package for Fedora/RHEL-family package managers. AppImage is no longer offered for this release. The packages install the executable, desktop launcher, and icon through the system package manager; there is no app-managed installer.

Choose a format whose dependencies your distribution can satisfy; package-family labels do not promise compatibility with every version. Download a newer package to update. No APT/YUM repository or automatic updater is configured. macOS and Windows installers and the separate MCP executable downloads retain their existing formats. See [Linux installation guidance](/guide/how-to/install-linux/).

## Other changes since 0.3.2

- AI-assisted document intake accepts pasted or local UTF-8 plain text and presents attributed candidates for review before capture. Binary document parsing, OCR, and remote wiki fetching are not built in.
- Independent vault views open with `Ctrl/Cmd` + `N`; `Ctrl/Cmd` + `W` closes a native window. Different vaults can run in separate processes.
- A continuous entity sidebar and saved-query navigation make existing vault content easier to reach. Query completion timing, transcript/predicate/settings layouts, and conflict-loading feedback have also been improved.
- New vaults bootstrap only the claim predicates `disputes`, `contradicts`, and `supports`. Adopt a vocabulary or define schema for domain predicates such as `owns` or `depends-on`; existing vault schemas are retained.
