User guide

Work with a Claimframe vault.

The mechanics of creating a local assertion memory: organize work into vaults, adopt shared vocabulary, capture sourced claims, ask focused questions, recall context, and reconcile disagreement without erasing it.

On this page Vaults Accelerators Vocabularies Capture Queries Recall Common workflows Reconciliation Making good models
01 · Vaults

Keep each body of work in a local vault.

A vault is a local SQLite file containing its assertions, sources, entities, predicates, saved queries, adopted vocabularies, and provenance. The current vault is the context for every capture and query in the app.

Create a vault

From the start screen, choose New vault and select where to save it. Normal vaults start empty, so pick a location you already back up and give the file a name that identifies the client, system, or engagement.

Open or switch vaults

Use a recent vault on the start screen, or open the app menu and choose Manage vaults. Open a vault in the current window to switch context, or in a new window to work with two vaults side by side.

Rename the display name

In Manage vaults, choose Rename. This changes the name shown by Claimframe; it does not move or rename the SQLite file.

Back up the file, not an account.

Claimframe is local-first. The vault file is the authoritative store. Close or pause writers before making a manual copy, and keep the vault with the project’s normal encrypted backup process.

03 · Vocabularies

Adopt shared terms without flattening local knowledge.

A vocabulary is an immutable release of reusable terms, predicates, and optional schema or general knowledge. A vault works without one; adopt a vocabulary when stable identifiers or a shared domain language will improve capture and recall.

foaf:FOAF 0.99People, organizations, groups, projects, documents, accounts, and relationships.Read the vocabulary guide → dcterms:Dublin Core Metadata TermsDescriptive metadata for documents, datasets, software, standards, and other resources.Read the vocabulary guide → rdf: · rdfs:RDF/RDFS 1.1Classes, properties, labels, domains, ranges, and basic schema relationships.Read the vocabulary guide → owl:OWL 2 CoreFormal ontology terms for equivalence, disjointness, restrictions, keys, and property behavior.Read the vocabulary guide →
Open the library

Open the app menu and choose Manage vocabularies. Select a bundled release, or use Import file to preview a local .cfvocab package.

Review before adopting

Check the namespace, publisher, license, release, attribution, included terms, predicates, statements, and local name collisions. Collisions do not overwrite local names; Claimframe shows the alternate vault token it will use.

Choose what enters the vault

Select terms, predicates, and—when available—general knowledge. Choose Adopt vocabulary. Imported terms and predicates then appear in capture and query autocomplete.

Undo only while unused

An imported release can be undone until vault data depends on it. Once an assertion, saved query, or another vocabulary uses its terms, Claimframe keeps the release in place and explains the dependency.

One release per vocabulary ID.

The current importer does not upgrade or compare releases. If the vault already contains that vocabulary ID, another release is blocked.

04 · Capture

Write the claim first; attach its context as you go.

Capture accepts a compact subject–predicate–object statement. Autocomplete suggests existing entities, predicates, sources, tags, and vocabulary terms, helping the vault reuse canonical names instead of creating near-duplicates.

subject predicate object @source ^evidence !status %confidence #tag
@sourceWho or what made the claim: a person, call, document, or repository.
^evidenceA locator such as a timestamp, section, URL fragment, or commit ID.
!statusThe assertion state. Defaults to active.
%confidenceA decimal from 0 to 1. Defaults to 1.0.
#tagA retrieval aid. Add more than one tag when useful.
?An object known to exist whose value is not yet known. Claimframe marks it for review.

Examples with progressively richer context

customer-portalCreate or reuse one entity without making a claim.
billing-service owns invoice-generationA minimal assertion. Source and other metadata remain optional.
billing-service owns invoice-generation @alice #ownershipAdd the source and a retrieval tag.
billing-service owns invoice-generation @alice ^00:32:18 !confirmed %0.84 #ownership #billingCombine evidence, status, confidence, and multiple tags.
billing-service owns ? @client-call #missing-ownerRecord that a value exists but is not yet known.
billing-service deployed-to us-east-1, us-west-2 @platform-team #deploymentUse commas for multiple object values when the predicate permits them.

Quoted entity names

Double quotes make a multi-word subject or object one term. Autocomplete adds quotes automatically when a known entity name contains spaces.

"Order Management Service" depends-on postgres @architecture-teamThe quoted subject is one entity.
customer-portal calls "Identity API" @repo:customer-portal ^commit:9f32c1The quoted object is one entity.
billing-service named "Billing Service" @architecture-doc #namingGive an entity a human-readable name.
billing-service aka "Billing App" @alice #nicknameAdd a non-canonical name that can resolve back to the entity.

Claims about claims

Use claim:ASSERTION_ID as the object when the new assertion evaluates an existing claim transaction rather than a domain entity. Keep the new source and rationale evidence attached; the original claim remains intact.

bob disputes claim:ASSERTION_ID @client-call ^00:48:51 #disputeRecord an explicit, sourced disagreement.
architect supports claim:ASSERTION_ID @review-notes ^decision-7 #judgmentRecord sourced support for an existing claim.

The live parsing reflection shows how Claimframe has interpreted each field before you commit. If you selected a source in the sidebar and omit @source, Claimframe adds that source to the capture.

05 · Queries

Use the same three-part shape to ask the vault.

A query is a subject–predicate–object pattern. Put ? in any position you want Claimframe to match. Exact terms narrow the result; ? ? ? returns all assertions.

? owns invoice-generationWho or what owns invoice generation?
billing-service ? ?What does the vault say about the billing service?
? depends-on postgresWhat depends on Postgres?
? ? ?Show every assertion in the current vault.

Query multi-word entity names

Use the same double-quote rule as capture. A quoted name occupies one query position and can resolve through the entity’s canonical name or aliases.

"Order Management Service" ? ?Everything asserted about the named service.
? calls "Identity API"Every subject that calls the named API.
"Order Management Service" depends-on postgresA fully specified assertion pattern with a quoted subject.
? named "Billing Service"Find the entity with that human-readable name.

Run queries from Graph Recall or Assertions. Autocomplete reuses canonical vault tokens. In assertion lists, select the subject, predicate, object, source, status, or tag on a row to pivot directly into a related filtered view.

Save useful queries

After entering a query, choose the save control, give it a clear name, and save it. Saved queries live inside the current vault. Open the app menu and choose Manage queries to run, rename, or delete them.

06 · Recall

Choose list recall for precision and graph recall for context.

Assertions is the direct route to a filtered, scannable result set. Graph Recall turns the same query results into entities and relationships, with the matching sourced assertions kept alongside the graph.

Start with a focused query

Enter the smallest subject–predicate–object pattern that describes what you need. Use source, predicate, object, status, and conflicts-only filters to reduce a busy result.

Inspect the evidence

Select an assertion row or graph edge to open its provenance. Review source, evidence locator, capture method, confidence, status, tags, and related events before repeating the claim.

Explore the neighborhood

On the graph, select a node and add inbound or outbound relationships. Drag nodes to keep the working subgraph readable; Claimframe remembers their positions.

Carry the result forward

Use Copy Citation for one sourced assertion, or use Export to copy the vault assertions as Markdown for notes, documentation, or handoff.

07 · Common workflows

Two reliable paths from evidence to recall.

Manual capture during a conversation

Open a fresh composer

Press Cmd/Ctrl + Shift + C, or open Capture. The shortcut clears the existing draft and focuses the composer.

Write the smallest useful assertion

Start with subject, predicate, and object. Add @source immediately when attribution matters, then attach an evidence locator, confidence, status, or tags as available.

Reuse vault terms

Choose autocomplete suggestions for existing entities, aliases, predicates, sources, and vocabulary terms. Use Cmd/Ctrl + Space to reopen suggestions, arrows to move, and Tab to insert.

Check the parse

Read the live subject, predicate, object, and metadata reflection below the composer. Correct any unexpected split or missing quote before committing.

Commit and verify

Press Enter or choose Commit. Select the new item in Recent Assertions and inspect its provenance when the claim will drive a decision or handoff.

Transcript capture and review

Import the source

Open Source Intake. Paste timestamped transcript text or choose Load Transcript File, then choose Import Transcript. Claimframe creates an isolated review run and ordered source segments.

Inspect the timeline

Confirm speaker names, timestamps or sequence numbers, and segment text in Transcript Timeline. This imported text is the evidence candidates will point back to.

Extract candidates

Select a configured AI model and choose Extract claims. Configure a provider in Application settings if necessary. Extraction creates review candidates—not assertions—and automatically opens Transcript Claims when ready.

Choose the review run

In Transcript Claims, select the transcript/review run. Use the Remaining, Accepted, Deferred, and Rejected tabs and the progress summary to control the queue.

Compare proposal to evidence

Select a candidate. Read the exact source words and the Source, Speaker, Timestamp, Sequence, extraction, and provider details in Transcript Evidence. Use Open in Source Intake when you need the surrounding timeline.

Edit and validate

Correct the proposed subject, predicate, or object. Claimframe resolves each field against the same entities, aliases, predicate schema, and claim-reference rules as manual capture. Errors block acceptance; warnings require deliberate confirmation.

Decide each candidate

Save edits keeps an unfinished proposal. Accept creates the sourced assertion. Defer keeps it unfinished for later. Reject records the review decision without creating an assertion. Accepted and rejected candidates become immutable.

Finish the run

A review is complete when every candidate is accepted or rejected. Extraction issues remain visible separately; inspect any quarantined malformed proposal rather than treating it as evidence.

Already structured transcript lines?

When segments already contain Claimframe capture syntax, Prepare structured claims can parse deterministic candidates without asking a model to interpret natural language.

08 · Reconciliation

Record judgment without declaring the disagreement gone.

The Conflicts workspace separates four things: original source assertions, explicit disagreement claims, the currently derived conflict condition, and the analyst’s persisted judgment. A judgment adds interpretation and provenance; it does not close, retract, overwrite, or hide the conflict.

Choose a dossier

Open Conflicts. Search the conflict queue or filter it by Needs judgment, Judgment recorded, or Needs re-review. Selecting a group opens its dossier with the detection basis, stable signature, and explicit Conflict active condition.

Review equal-weight evidence

In Evidence mode, compare every participating assertion, source, evidence locator, and capture time. Selecting a row synchronizes the provenance inspector and preselects that claim transaction as a possible judgment target.

Explore surrounding relationships

Switch to Explore relationships when local context will help. Select claim transactions—not ordinary entity nodes—as judgment targets. Use the visible Add neighbors action or N to add context; neighboring claims do not become conflict members merely because they are shown.

Set analyst attribution

The judgment composer uses the analyst identity from Application settings. Claimframe resolves that label to an entity in the current vault. This is attribution convenience, not authenticated identity.

Add the judgment assertion

Choose a claim-reference relationship such as supports, disputes, or contradicts; choose the target assertion and source; then write the required rationale. Add judgment assertion appends a new sourced claim and immutable review metadata at the current vault transaction.

Read the result correctly

Original assertions remain under Original assertions. The new claim appears separately under Analyst judgments. The condition still reads Conflict active, while the workflow state becomes Judgment recorded.

Report or revisit

Open View report to copy or export Markdown containing the current derivation, source assertions, judgment, rationale, review basis, and changes since review. New participating evidence or schema changes move the case to Needs re-review.

Conflict state and review state are independent.

A conflict may remain active after a well-supported judgment. Reconciliation in Claimframe means preserving the evidence and recording accountable interpretation—not manufacturing a single timeless truth.
